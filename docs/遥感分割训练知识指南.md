# 遥感语义分割训练知识指南

> 基于 SSRS 项目 Plan1-4 的实验经验总结。最后更新: 2026-05-08。

---

## 1. 评估：什么指标重要、为什么

### 1.1 四项必须输出的指标

每次评估必须同时输出四类指标，缺一不可：

| 指标 | 公式 | 说明 |
|------|------|------|
| **Overall OA** | (全部预测正确的像素) / (全部有效像素) | 整体像素准确率 |
| **Overall mIoU** | mean(per-class IoU) | 逐类平均 IoU，对类别不平衡敏感 |
| **Per-class IoU** | TP / (TP + FP + FN) | 每个类别的交并比，不含 TN |
| **Per-class OA** | (TP + TN) / (TP + TN + FP + FN) | 每个类别的像素准确率，含 TN |

### 1.2 IoU vs OA：为什么两者都需要

```
IoU（交并比）: 只关心该类别的预测是否精确
  → 小类别（如 Car）的 IoU 通常很低，因为 FP/FN 占比大
  → 不受背景像素数量影响

OA（准确率）: 关心所有像素（包括背景）是否预测正确
  → 小类别（如 Car）的 OA 通常很高（>95%），因为 TN 占主导
  → MFNet 论文用逐类别 OA 来展示大类别（Building, Road）的性能
```

**关键洞察**: MFNet 论文 Table I 报告的是逐类别 **OA**（不是 IoU）。当你跟 MFNet 对比时，必须用 per-class OA 对齐，否则数字会差很多。

### 1.3 Per-class OA 的推导

不需要额外累加器，从已有 inter/union 直接计算：

```
TN = total_valid_pixels - TP - FP - FN
   = total - (TP + FP + FN)
   = total - union[c]

OA_c = (TP + TN) / total = (inter[c] + total - union[c]) / total
```

### 1.4 为什么必须用 256² 滑动窗口

MFNet 论文和 ISPRS 标准使用 256×256 滑动窗口 + overlap 平均（stride=128）。

| 评估方式 | 问题 |
|---------|------|
| 512² crop（整块裁剪） | 系统性低估，Potsdam 差 27pp |
| 1008² 滑动窗口 | 高估（模型在该分辨率训练） |
| **256² 滑动窗口** | 学术界标准，可直接与 MFNet 对比 |

## 2. 类别映射与混淆模式

### 2.1 ISPRS 类别对应

| 我们 | MFNet 论文 | 英文 | 像素占比（Vaihingen） |
|------|-----------|------|---------------------|
| road | Impervious Surface | impervious_surface | 大（~30%） |
| building | Building | building | 大（~25%） |
| grass | Low Vegetation | low_vegetation | 中（~15%） |
| tree | Tree | tree | 大（~20%） |
| car | Car | car | 极小（<1%） |

> **注意**: ISPRS 原始有 6 类（含 clutter/背景杂物），所有实验都去除 clutter，只用 5 类。

### 2.2 最常见的混淆

| 混淆对 | 原因 | 影响 |
|--------|------|------|
| **Grass ↔ Tree** | 纹理相似，边界不规则 | Grass IoU 最低（~60%） |
| **Road ↔ Building** | 屋顶和路面颜色相近 | Road 边界模糊 |
| **Car ↔ Road** | Car 极小且嵌在 Road 中 | Car IoU 只有 ~67% |
| **Grass ↔ Road** | 草地和路面边缘过渡 | 边缘精度差 |

### 2.3 各类别难度

- **Building（最简单）**: 几何形状规整，边界清晰，IoU ~86%
- **Tree / Road（中等）**: 形状不规则但面积大，IoU ~75%
- **Grass（困难）**: 纹理特征弱，与 Tree 高度混淆，IoU ~60%
- **Car（最困难）**: 面积极小（<1% 像素），几乎没有空间上下文，IoU ~67%

## 3. 微调策略：什么有效、什么无效

### 3.1 已验证的结论

| 策略 | 结果 | 原因 |
|------|------|------|
| ✅ **VPT Adapter (2.1M)** | **最好 (73.10% mIoU)** | 保留 SAM 预训练知识，只训练少量 adapter |
| ✅ **LoRA r=8 (15M)** | 好 (72.87% mIoU) | 同样参数高效，略低于 Adapter |
| ❌ **全量微调 ViT (456M)** | 差 (72.49% mIoU) | 12 张图不足以支撑 456M 参数训练，过拟合 |
| ❌ **只训练 FPN Decoder (0.8M)** | 更差 (56.6% mIoU) | Decoder 太弱，无法学习 text-vision 对齐 |
| ❌ **DSM logit bias 后处理** | 灾难 (15.4% mIoU) | 直接相乘破坏 SAM3 精心训练的 logit 分布 |

### 3.2 核心原则

```
SAM 的通用知识 ⇄ 遥感特定知识 之间的平衡

  保留太多            ←→            适配太多
  (zero-shot)                     (full fine-tune)
  65.8% mIoU                      56.6% mIoU
                    最优点
              Adapter/LoRA (73%)
```

**原则**: 永远不要让 SAM3 的 ViT 全部可训练。用 Adapter 或 LoRA 注入遥感知识，同时保留预训练权重。

### 3.3 可训练参数 vs 性能

```
Adapter (2.6M)  → 73.10% mIoU  ← 最佳性价比
LoRA (17.3M)    → 72.65% mIoU
Full unfreeze   → 72.49% mIoU  ← 175× 参数，更差
```

## 4. DSM（数字地表模型）融合

### 4.1 融合时机决定效果

| 融合方式 | 效果 | 说明 |
|---------|------|------|
| **Late fusion**（ViT 输出后 SEFusion） | 小幅提升 | Plan3/4 用的方式，+1-2pp |
| **Early fusion**（ViT 每层内部 MMAdapter） | 大幅提升 | MFNet 用的方式，+8pp |
| **Input-level**（stack 4 通道） | 几乎无提升 | DSM 信息被 ViT 的 RGB 预训练权重淹没 |

**关键洞察**: MFNet 的 MMAdapter 在 ViT 每一层都做 RGB↔DSM 交叉融合，DSM 信号会参与 attention 计算。Plan3/4 的 SEFusion 是 ViT 处理完 RGB 后才融合 DSM，属于"晚融合"，DSM 无法影响 attention，提升有限。

### 4.2 DSM 预处理

```python
# DSM 归一化（必须）
dsm = (dsm - dsm.min()) / max(dsm.max() - dsm.min(), 1e-8)
```

DSM 值的物理范围差异很大（0-300m），不归一化会导致训练不稳定。

## 5. 训练超参数

### 5.1 MFNet Recipe（推荐）

```python
optimizer = SGD(lr=0.01, momentum=0.9, weight_decay=5e-4)
scheduler = CosineAnnealingLR(T_max=50)
warmup = 2 epochs (linear)
batch_size = 4
epochs = 50
crop_size = 256  # 训练用 256²
```

### 5.2 Adapter/LoRA Recipe（当前最佳）

```python
optimizer = AdamW(lr=1e-3, weight_decay=1e-4)
scheduler = CosineAnnealingLR(T_max=20)
batch_size = 4
epochs = 20
crop_size = 256  # 或 512（训练更快但最终指标略低）
```

### 5.3 关键超参数影响

| 参数 | 作用 | 建议 |
|------|------|------|
| **learning rate** | Adapter 用 1e-3，Full 用 0.01 (SGD) | 太高→不收敛，太低→学不到 |
| **weight decay** | Full 用 5e-4，Adapter 用 1e-4 | 防止过拟合 |
| **warmup** | Full training 需要 2 epoch warmup | 避免初期梯度爆炸 |
| **dropout** | Vaihingen 用 0.1，Potsdam 用 0.0 | Potsdam 数据多不需要 dropout |
| **crop size** | 256² 训练 → 256² 评估最匹配 | 512² 训练快但最终 mIoU 低 ~2pp |

## 6. 架构选择

### 6.1 Backbone

| Backbone | 参数量 | 适用场景 |
|----------|--------|---------|
| SAM1 ViT-H | 632M | MFNet 使用，遥感已验证 |
| SAM3 ViTDet | 454M | Plan3/4 使用，结构不同 |

SAM3 ViTDet 和 SAM1 ViT-H 的 ViT block 结构不同：
- SAM1: `blocks.0.norm1, norm2, attn, mlp`（标准 ViT）
- SAM3: `blocks.0.block.norm1, block.attn`（带 window attention 的 ViTDet）

### 6.2 Decoder

| Decoder | 参数量 | 特点 |
|---------|--------|------|
| Simple UNet | ~0.5M | 轻量，上采样+卷积 |
| UNetFormer (GLA) | ~6.5M (ch=256) / ~0.5M (ch=64) | 含 Global-Local Attention，边界更好 |
| MFNet Decoder | ~0.5M | UNetFormer with GLA, channels=64 |

**关键**: `decode_channels=64` 的 UNetFormer 只有 0.5M 参数，但性能和 `ch=256` (6.5M) 版本相当。ch=64 是更好的选择（参数少、不易过拟合）。

### 6.3 融合模块

| 模块 | 用途 |
|------|------|
| SEFusion | Squeeze-and-Excitation channel attention，融合 RGB+DSM |
| Pyramid4Scale | ViT 单尺度输出 → 4 个不同分辨率的特征金字塔 |
| DFM (MFNet) | 多尺度深度融合模块，在解码前做多尺度特征处理 |

## 7. 常见陷阱

### 7.1 多分类 argmax 高估性能

SAM3 的 per-class 二分类 IoU（~45%）远低于多分类 argmax IoU（~65%），因为 argmax 的竞争排斥效应隐藏了类间混淆。**评估时必须按 per-class 独立计算，不能做 argmax 后评估。**

### 7.2 Prompt 工程

SAM3 的 text encoder 只理解**单词级别的类别名称**。任何复杂 prompt（遥感术语、几何描述、同义词）都会灾难性地降低性能（-50% mIoU）。SAM3 的 text encoder 对遥感领域特定 prompt 是 OOD 的。

### 7.3 模型训练的评估时机

```
训练监控: 512² crop → 快但指标不准（低估）
中间参考: 1008² sliding → 偏向训练分辨率
最终评估: 256² sliding → 学术界标准，唯一可信
```

### 7.4 小数据 + 大模型 = 过拟合

Vaihingen 只有 12 张训练图（~960 个 256² patch）。456M 参数的 full training 在 epoch 6 就开始过拟合。**在 ISPRS 这种小数据集上，参数效率比参数数量更重要。**

### 7.5 代码版本兼容性

每个实验目录的代码版本不同。加载旧 checkpoint 时注意：
- `SeparableConvBN` 结构变化：旧版 `[dwconv, BN, pwconv]` → 新版 `[dwconv, pwconv, BN]`
- `decode_channels` 默认值：旧版 64 → 新版 256
- 使用 `eval_unified.py` 的 `--arch` 和 `--decode-channels` 参数可以自动处理这些差异

## 8. 性能里程碑

### 8.1 Vaihingen 演进历程

| 阶段 | mIoU | OA | 关键突破 |
|------|------|-----|---------|
| Plan1 Zero-shot | 65.8% | — | 基线：SAM3 不加任何微调 |
| Plan1 FPN fine-tune | 56.6% | — | ❌ 微调比零样本差 |
| Plan2 Threshold tune | 55.4%* | — | Per-class 二分类视角 |
| Plan3 Route A (512²) | 70.0% | — | ✅ 首次超过零样本 |
| Plan3 Route A (256²) | 73.0% | 86.5% | ✅ 256² 窗口训练 |
| **Plan3 MFNetDec DSM** | **73.10%** | **86.45%** | 🏆 当前最佳 |
| Plan4 Full SGD | 72.49% | 86.38% | ❌ 更多参数、更低性能 |
| **MFNet (SAM1, target)** | **85.03%** | **92.97%** | 🎯 奋斗目标 |

*注: Plan2 用的是 per-class binary IoU，与多分类 mIoU 不可直接比较。

### 8.2 与 MFNet 的差距根源

我们的最佳模型 (73.10%) 离 MFNet (85.03%) 还差 12pp。主要差距来源：

1. **融合时机**（最大影响）: 我们是 late fusion (SEFusion)，MFNet 是 in-ViT early fusion (MMAdapter)
2. **Backbone**（中等影响）: 我们 SAM3 ViTDet，MFNet SAM1 ViT-H
3. **微调方式**（中等影响）: 我们 VPT Adapter，MFNet MMAdapter（更强的多模态 Adapter）
4. **训练策略**（小影响）: 我们 20 epoch AdamW，MFNet 100+ epoch SGD+momentum

## 9. 概念速查表

| 概念 | 一句话解释 |
|------|----------|
| **mIoU** | 先算每类 IoU，再取平均。小类别贡献相同权重。 |
| **OA** | 正确像素 / 总像素。大类别主导，小类别被淹没。 |
| **Per-class OA** | 每类单独算 OA（含 TN）。小类别 OA 虚高（TN 主导）。 |
| **Adapter** | ViT block 里插入小型可训练模块（下投影→ReLU→上投影），冻结 ViT 主体。 |
| **LoRA** | 在 nn.Linear 旁加低秩矩阵 BA，只训练 A 和 B。 |
| **VPT (Visual Prompt Tuning)** | 在 ViT 输入序列前加可学习的 prompt token，等价于 Adapter 的一种。 |
| **SEFusion** | Squeeze-and-Excitation：先全局池化→FC→sigmoid→通道加权，简单有效的融合。 |
| **GLA (Global-Local Attention)** | UNetFormer 的核心：窗口自注意力 + 局部卷积分支 + 十字形聚合。 |
| **DFM (Deep Fusion Module)** | MFNet 的金字塔多尺度处理：对深层特征做多尺度卷积后融合。 |
| **Sliding window 256²** | 256×256 窗口在整图上滑动，重叠区取平均。ISPRS 标准评估方式。 |
| **Clutter** | ISPRS 数据集中的"背景杂物"类（水体、碎片等），所有实验移除。 |
| **DSM (Digital Surface Model)** | 数字地表模型，每个像素的高程值。与 RGB 像素对齐的额外模态。 |
